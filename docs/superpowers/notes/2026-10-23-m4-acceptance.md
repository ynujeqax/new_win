# M4: приймання (2026-10-24)

Специфікація: [2026-10-23-newwin-m4-settings-design.md](../specs/2026-10-23-newwin-m4-settings-design.md). План: [2026-10-23-newwin-m4-settings.md](../plans/2026-10-23-newwin-m4-settings.md).

## Виміри

| Що | Результат | Ціль |
|---|---|---|
| Простій 10 хв, CPU (2026-10-24, Settings закрито, без `NEWWIN_DEBUG`, ПК не чіпали) | **0.0016 %** shell (main +31 мс, решта 0–16 мс); watchdog 0.0003 % | ≈ 0 % |
| RAM shell (private WS) | пік **20.1 MB** (пристрій D3D ще теплий, звільняється через 60 с простою, як у M3 — 17.3 MB); у простої **11.3 MB**; watchdog 1.3 MB; перезапусків не було | ≤ 10.7 MB — **перевищено на 0.6 MB, прийнято користувачем** |
| Запис `config.toml` → `config applied` у shell (5 проб) | **57.5–69.2 мс** (з них 50 мс — debounce) | — |
| Повзунок → кадр бару | ≈ **160–170 мс** (100 мс debounce запису в Settings + 58–69 мс) | < 100 мс — **не досягнуто, прийнято**: обидва debounce задані планом, повзунки на живій перевірці відчуваються наживо |
| Перший кадр Settings (`app window first-frame-ms`) | **10.5 / 13.1 мс** | < 200 мс |
| Перший кадр бару | 55 мс | — |

Пам'ять: +1.1 MB від M3 (10.2 → 11.3 MB) найімовірніше дають модулі WinRT для Wi-Fi (задача 7b, `MobileNetworking.dll` серед завантажених) — ціна справжнього сигналу без дозволу на розташування. Якщо колись треба буде повернутися під 10.7 MB — вивантажувати ці модулі між оновленнями сигналу.

## Живий чекліст (з користувачем, 2026-10-24)

- [x] Відкриття Settings: меню бару *NewWin settings…*, трей (клік і правий клік → *Settings…*), Spotlight `settings`, повторний запуск `NewWin.exe` — щоразу одне вікно на передньому плані; повторне відкриття піднімає наявне.
- [x] Скло вікна, також під час перетягування.
- [x] Bar: *Pinned* ↔ *Auto-hide* (робоча область), затримки показу/приховування, смуга-тригер 1/2 px — наживо.
- [x] Appearance: *Glass*, висота, відступ, заокруглення, розмір тексту — наживо; шрифт зі списку (клік, що відкриває список, нічого не вибирає; фільтр друкуванням); *Custom* дата з прикладом; секунди.
- [x] Items: перетягування й приховування (рядок лишається на місці).
- [x] Tray: перетягування й приховування іконки.
- [x] Spotlight: кількість результатів, клавіша Win, *Clear* з підтвердженням за 3 с.
- [x] Вікно: перетягування, `–`, Win+↓ (Snap свідомо немає — фіксований розмір).
- [x] Ручна помилка в `config.toml` → смуга «…has an error…» + *Open file*, бар не змінився; після виправлення смуга зникла.
- [x] *Start with Windows*: ключ `HKCU\…\Run\NewWin` → `"…\target\release\NewWin.exe"`.
- [x] *Restore Windows taskbar*: `quit requested` → shell і watchdog вийшли, рідний таскбар повернувся.

Рішення щодо вигляду (користувач): список шрифтів — усередині вікна, не окремим вікном; перемикачі в Items/Tray без підпису *Show*; ручка перетягування — лінії, не `⋮⋮`. Усе лишається як є.

## Рев'ю

Кожна задача пройшла рецензію (spec + якість). Фінальне рев'ю всієї гілки: 0 критичних, 5 важливих — виправлено в `94dd47d` (I1 `tray_seen.toml` більше не перезаписується на кожну зміну трею; I2 лічильники Spotlight не стираються до першого збереження; I3 Settings не показує типові значення для нечитабельного `config.toml` і не затирає його; I4 порядок трею для невидимих програм зберігається; I5 кеш exe за pid чиститься) і `8bbf6e0` (кожне атомарне збереження пише свій тимчасовий файл — два записувачі більше не псують файл). Плюс M1 (`sync_all` перед rename), M2 (лог «config missing» лише при зникненні), M4 (секунди не тікають, коли годинника не видно).

## Відкладено (дрібниці, не блокують)

- Restore при завислому shell: watchdog може перезапустити shell після `--restore-taskbar` (рідкісний випадок).
- `autostart_set(false)` не видаляє значення типу REG_EXPAND_SZ (сьогодні ніхто такого не пише) — до інсталятора.
- Сиротливий `.tmp` після аварії посеред збереження ніхто не прибирає.
- Settings: `view.rs` / `body.rs` великі (~870 / ~900 рядків); фокус-скрол після перетягування мишею; колесо під час перетягування не перераховує слот; немає автопрокрутки під час перетягування; клавіатурні переміщення без анімації; некоректний шаблон дати дає порожній приклад; каретка блимає в неактивному вікні; *Clear* і *Restore* не знімають підтвердження одне одного.
- Тести: нестабільні `crates/ui/tests/backdrop.rs::an_unchanged_screen_posts_nothing_more` і (один раз) `tray_seen.rs::missing_file_is_empty_and_round_trip_works`; кілька тестів лишають тимчасові теки.

## Рішення, ухвалені під час виконання

1. Restore у Settings (T10) шле `WM_APP + 20` раніше, ніж shell його обробляє (T12) — порядок задач.
2. Тест debounce в T4 перевіряє лише константи; поведінку перевірено наживо.
3. Команда Spotlight *Settings* відкриває налаштування NewWin; налаштування Windows — з меню бару.
4. Автозапуск увімкнувся сам (`start_with_windows = true`) — поведінка зі специфікації.
5. Трей запам'ятовує побачені програми на кожну зміну трею, не лише коли панель відкрита (spec §4.4).
6. Виправлення Wi-Fi (WinRT `GetSignalBars`) вставлено як задачу 7b в гілку M4.
7. Snap прибрано: вікно фіксованого розміру 760×560 (погоджено; spec виправлено в `a2cce28`).
8. Розділи Settings — окремі файли `apps/settings/src/sections/*.rs`.
9. Список шрифтів — оверлей усередині вікна (користувач погодив на живій перевірці).
10. Залишкову ваду з тимчасовим файлом після фінального рев'ю виправлено окремим малим комітом.
11. Повзунок → бар ≈ 160–170 мс замість < 100 мс прийнято (debounce з плану); пам'ять 11.3 MB замість 10.7 MB прийнято користувачем.
