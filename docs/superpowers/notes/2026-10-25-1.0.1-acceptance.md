# 1.0.1: приймання (2026-10-25)

Специфікація: [2026-10-25-newwin-1.0.1-icons-design.md](../specs/2026-10-25-newwin-1.0.1-icons-design.md) (§9 — доповнення після живої перевірки). План: [2026-10-25-newwin-1.0.1-icons.md](../plans/2026-10-25-newwin-1.0.1-icons.md). Гілка `v1.0.1-icons`.

## Що зроблено

- Кольорові іконки Windows на барі (запущені програми), у Spotlight і в списку трею; проявлення 150 мс, місце під іконку резервується одразу.
- Запасні джерела: exe вікна для Chromium-ідентифікаторів без запису в «Пуску» (Helium), exe процесу для рядків трею без `hIcon`, `NewWin.exe` для рядка NewWin, `NewWinSettings.exe` для команди *NewWin Settings*, NVIDIA Control Panel для іконки NVIDIA (її процес працює від SYSTEM).
- Трей-хост тримає власну копію кожної іконки трею (`CopyIcon`): програми знищують свою одразу після `Shell_NotifyIcon`.
- Shell-іконки дістає `NewWin.exe --icon-helper`: компоненти Windows для іконок (`Windows.UI.Xaml`, `StartTileData`, пули потоків) не вивантажуються, тож вони живуть у помічнику, а не в shell. Помічник закривається через 30 с без запитів.
- Меню бару (і підменю) лишається прозорим до першого кадру скла, не довше 250 мс, як Spotlight: більше немає чорного кадру на 10–20 мс (знайшов користувач; тести `crates/ui/tests/popup.rs`).

## Виміри

| Що | Результат |
|---|---|
| Пам'ять shell, іконки в самому shell (перша збірка 1.0.1, 10 хв) | 29.5 MB пік, 53 потоки — **не пройшло** (1.0.0: 14.8 MB) |
| Пам'ять shell з помічником, після старту й показу іконок | **8.0 MB**, 19 потоків; помічник 2.6 MB, 8 потоків, вийшов за ~30 с після останнього запиту |
| Тести / clippy | 491 зелені, clippy чистий |
| Setup | `NewWin-Setup-1.0.1.exe`, 2.9 MB |

10-хвилинний замір простою з помічником користувач скасував (немає часу); простій CPU не заміряний для остаточної збірки.

## Фінальне рев'ю

Рецензент (opus), уся гілка до `a89d4cb`: 0 критичних, 1 важлива — виправлено в `5e9e826` (копія іконки трею, тест RED→GREEN). Помічний процес (`f55aa60`) з'явився після рев'ю — окремим рецензентом не перевірений.

## Рішення

1. Повтор `E_PENDING` (до 10 × 30 мс) у `shell_icon`.
2. Premultiply лише для прямої альфи (колір більший за альфу).
3. Іконки Spotlight просить сама панель дією `SpotlightOp::Icons` на кожен запит із результатами.
4. Рядки трею без проявлення; виділення тримається за підписом.
5. Без лічильника в `IconKey::Tray` для звільнених копій (у дескрипторах USER є лічильник повторного використання).
6. Тести `backdrop.rs` читають живий екран і інколи падають, поки користувач працює з NewWin; з закритим NewWin — зелені.

## Відкладено (дрібниці з рев'ю)

- Програма, що анімує іконку трею при відкритому списку, може витіснити іконки бару з кешу (вони проявляться ще раз).
- `IconBitmaps` порівнює D2D-пристрій за адресою.
- Рядки трею заповнюють `icon_arrived`, хоча не проявляються.
- `process_image_path` для рядків без `hIcon` на кожне оновлення (без кешу за pid).
- `TrayList::paint` викликає `visible()` для кожного рядка.
- `Canvas::new` не перевіряє `CreateCompatibleDC`.
- Шлях `NIF_ICON` з `hIcon = 0` без тесту, що падає.
