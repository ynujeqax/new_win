## Що зроблено (коротко)

- Бар: автоприховування за наведенням на 1–2 px зверху, закріплений режим, програми зліва (групи, список вікон), дата/час справа, меню ПКМ з усіма пунктами Win+X + Settings/Restart/Quit NewWin.
- Сторож (watchdog): перезапуск після падіння, повернення рідного таскбару, перевірка зависань.
- Рендер на WARP: простій 0 мс CPU, ~5 МБ пам'яті.
- Виправлені баги з живого тестування:
  - втрата повідомлень під час ShellExecute/COM (Settings з'являлось пізно, кліки через раз, бар не ховався) — черга `DEFERRED` у `crates/platform/src/window.rs`;
  - Screen Snipping і PopupHost на барі — фільтр `shell_ui`/`no_activate`;
  - «New window» для Helium/Chrome нічого не відкривав (ідентифікатор вікна з профілем не зареєстрований у меню Пуск) — тепер запускається .exe вікна (`new_instance_target`, коміт 36c4eb9). Користувач підтвердив, що працює.

## Відкрите питання №1: бар іноді «висить» сам по собі

- Наведення/відведення ховає його правильно; зависання буває без участі користувача.
- Гіпотеза «меню перекриває зону на 2 px» не підтвердилась.
- Додано журнал (log::debug!, вмикається `NEWWIN_DEBUG=1`): показ/приховування вікна бару зі станом автомата, animate in/out, hide timer, перестворення графічного шару, mouse leave, всі входи автомата видимості.
- Що робити: коли користувач скаже «завис» (і не наводив мишу), прочитати `%LOCALAPPDATA%\NewWin\logs\newwin.log` навколо цього часу; шукати `bar window shown` без `animate in`, `ZoneEnter` без `ZoneLeave`, `OverlayOpened` без `OverlayClosed`, `fullscreen`. Далі — одна гіпотеза, тест RED→GREEN, фікс, живий тест.
- Запуск з журналом: `$env:NEWWIN_DEBUG="1"; Start-Process .\target\release\NewWin.exe`.

## Обмеження й нюанси середовища

- `cargo` і `git` не в PATH сесії: `$env:Path="$env:USERPROFILE\.cargo\bin;$env:Path"`, git — `C:\Programs\Git\cmd\git.exe`.
- Перед збіркою release зупиняти NewWin: `Get-Process NewWin | Stop-Process -Force`.
- Не запускати Screen Snipping за користувача; ніколи не тиснути Shut down / Restart / Sign out / Sleep у тестах.
- Знімки екрана — тільки DXGI-інструментом (`crates/ui/examples/screenshot.rs`), GDI на HDR дає старі кадри.
- У PowerShell P/Invoke передавати `[NullString]::Value`, а не `$null`.
