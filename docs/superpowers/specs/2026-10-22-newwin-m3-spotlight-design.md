# NewWin M3: Spotlight (доповнення до дизайну)

Дата: 2026-10-22
Статус: погоджено з користувачем, чекає рев'ю специфікації

Доповнює [2026-10-21-newwin-design.md](2026-10-21-newwin-design.md), §2 «Spotlight» і §9 «Spotlight». Де вони розходяться, діє цей документ. Увесь вигляд — за [2026-10-22-newwin-liquid-glass-design.md](2026-10-22-newwin-liquid-glass-design.md).

## 1. Що погоджено з користувачем

- Порожній запит — **лише поле вводу**, без списку (варіант A). Ні «Recent», ні «Top apps», ні «Quick searches».
- **Меню рядка** (як контекстне меню рідного «Пуску», але скляне й текстове): *Open* · *Run as administrator* · *Open file location*. *Pin to Start / taskbar* немає (закріплених програм у v1 немає). Власні пункти програм із jump list (наприклад, «Windows PowerShell ISE») відкладено: офіційного API читати чужі jump list немає.
- **Пошук в іншій розкладці** (варіант A): запит, набраний не в тій розкладці, перекладається `ENG` ↔ `UKR` і теж шукається; ці результати йдуть після прямих.
- **Джерело програм — `shell:AppsFolder`** (підхід A): той самий список, що в рідному «Пуску», класичні й UWP разом.
- Решту технічних рішень користувач делегував. Стиль — рідке скло, плавно, монохром, «сексі пексі».

## 2. Поведінка

### 2.1. Відкриття й закриття

- **Відкривають:** окреме натискання Win (Win down → Win up без інших клавіш між ними), `Ctrl+Esc`, клік по лупі на барі (елемент `search` у `items.right`, між гучністю й роздільником).
- Комбінації Win+E, Win+R, Win+Shift+S тощо проходять без змін.
- Win або `Ctrl+Esc` при відкритому Spotlight **закривають** його.
- **Закривається:** `Esc`, запуск, клік поза вікном, втрата фокусу. Поки відкрите меню рядка, Spotlight не закривається (так само, як трей під меню програми в M2); закривається, коли фокус іде не в меню.
- При кожному відкритті поле порожнє, нічого не вибрано.
- `spotlight.win_key = false` у конфігу: Win не перехоплюється (рідний «Пуск» відкривається, хоча й без таскбару), `Ctrl+Esc` теж; лупа працює.

### 2.2. Пошук і ранжування

Чиста функція в `crates/core/src/spotlight.rs`. Порівняння без урахування регістру (`to_lowercase` за Unicode), пробіли на краях запиту відкидаються.

**Рівні збігу** (від кращого):
1. **Префікс назви:** `ste` → **Ste**am.
2. **Початок слова:** `code` → Visual Studio **Code**. Межа слова — після пробілу, `-`, `_`, `.`, `(` або на переході з малої літери на велику (`PowerShell` → `Shell`).
3. **Підрядок:** `ord` → Disc**ord**.
4. **Підпослідовність:** `vsc` → **V**isual **S**tudio **C**ode. Літери запиту трапляються по порядку. Спершу пробується збіг лише на початках слів (жадібно зліва); якщо не вийшло — жадібно найлівіші літери.

**Порядок:** рівень → (для однакового рівня) кількість запусків з `usage.toml` за спаданням → назва за алфавітом (без регістру). Показується до `spotlight.max_results` (за замовчуванням 8) рядків.

**Інша розкладка:** якщо запит містить літери, його переклад за фізичними клавішами `ЙЦУКЕН` ↔ `QWERTY` (українська розкладка: `і`↔`s`, `ї`↔`]`, `є`↔`'`, `ґ`↔`\`, `'`↔`` ` `` тощо — повна таблиця в `crates/core`) ранжується так само. Ці результати додаються **після** прямих, без дублів (та сама програма лишається на кращому місці). Якщо переклад дорівнює запиту, він не шукається.

**Виділення:** результат несе діапазони символів збігу (у вихідній назві), вікно малює їх жирним. Для підпослідовності — кожна літера окремо.

**Нічого не знайдено:** один приглушений рядок «No results», його не можна вибрати.

**Системні команди** ранжуються разом із програмами, тип *System*:

| Назва | Дія |
|---|---|
| Settings | поки відкриває `%APPDATA%\NewWin\config.toml` (вікно налаштувань — M4) |
| Shut down | `shutdown.exe /s /t 0`, **потрібен другий `↵`** |
| Restart | `shutdown.exe /r /t 0`, **потрібен другий `↵`** |
| Sleep | `SetSuspendState` (наявний `SystemTarget::Sleep`) |
| Lock | `LockWorkStation` |
| Sign out | `ExitWindowsEx(EWX_LOGOFF)` (наявний `SystemTarget::SignOut`) |

Системні команди теж мають лічильник запусків (ключ `system:<назва>` у `usage.toml`). Системна «Settings» (NewWin) і програма Windows «Settings» обидві в списку з різними типами; за однакового рівня й однакової кількості запусків *App* іде перед *System*.

### 2.3. Подвійне підтвердження

Перший `↵` (або клік) на Shut down / Restart не виконує дію, а міняє текст рядка на «Press ↵ again to shut down» / «Press ↵ again to restart». Другий `↵` на тому ж рядку виконує. Підтвердження скидається, якщо змінився запит, вибір перейшов на інший рядок або минуло 3 с. Автомат — у `crates/core` (чиста функція від подій і часу).

### 2.4. Клавіші й миша

| Ввід | Дія |
|---|---|
| друк, `Backspace`, `Ctrl+Backspace` (слово), `←` `→` `Home` `End`, `Ctrl+A`, `Ctrl+V` | редагування поля (один рядок; вставка — перший рядок буфера, до 200 символів) |
| `↑` `↓` | вибір рядка (по колу); перша літера запиту вибирає перший рядок |
| `↵` | запустити вибраний (без вибору — перший) |
| `Ctrl ↵` | запустити від імені адміністратора (лише для програм, що це підтримують) |
| клавіша меню, `Shift+F10`, правий клік по рядку | меню рядка |
| лівий клік по рядку | запустити |
| наведення | м'яка пігулка наведення (як у треї), вибір не змінює |
| `Esc` | закрити (спершу закриває меню рядка, якщо відкрите) |

### 2.5. Меню рядка

Наявний скляний `Popup` (`crates/ui/src/popup.rs`), біля рядка (від правого кліку — у точці кліку).

| Пункт | Коли є | Дія |
|---|---|---|
| **Open** | завжди | як `↵` |
| **Run as administrator** | класичні програми (є шлях до файлу) | `ShellExecuteEx` з дієсловом `runas` на `shell:AppsFolder\<id>` |
| **Open file location** | є шлях до файлу | `SHOpenFolderAndSelectItems` на ціль (для ярлика — файл, на який він вказує; якщо ціль недоступна — сам ярлик) |

Для UWP-програм лишається лише *Open*. Для системних команд меню не відкривається.

### 2.6. Запуск

- Класичні й UWP: `ShellExecuteEx` на `shell:AppsFolder\<AppUserModelID або ParsingName>` (так само запускає «Пуск», працює для обох видів; `IApplicationActivationManager` не потрібен).
- Після успішного запуску: Spotlight ховається, лічильник програми +1.
- Помилка запуску (у тому числі відмова в UAC): Spotlight ховається, у журнал `log::warn!`, лічильник не змінюється.
- **`usage.toml`:** `[launches]`, ключ — ідентифікатор програми (`ParsingName`), значення — кількість. Читається при старті; запис — у Worker-потоці, не частіше разу на 2 с (зміни між записами об'єднуються). Записується через тимчасовий файл і перейменування. Пошкоджений файл: журнал, лічильники з нуля, файл перезаписується при наступному запуску. Записи програм, яких більше немає в індексі, видаляються при записі.

## 3. Індекс програм (`crates/platform/src/apps_index.rs`)

- Перелік `shell:AppsFolder` через `SHGetKnownFolderItem(FOLDERID_AppsFolder)` → `BindToHandler(BHID_EnumItems)` → `IEnumShellItems`. Для кожного елемента:
  - **назва** — `SIGDN_NORMALDISPLAY`;
  - **ідентифікатор** — `SIGDN_PARENTRELATIVEPARSING` (AUMID для UWP, шлях або Known Folder GUID-шлях для класичних);
  - **шлях до файлу** — `PKEY_Link_TargetParsingPath` або `System.ItemPathDisplay` / `PKEY_ParsingPath`, якщо він веде на файл на диску (проба 3 уточнює, яка властивість працює); немає шляху → UWP-подібна програма;
  - **чи це UWP** — наявність `PKEY_AppUserModel_PackageFullName` (або `System.AppUserModel.PackageInstallPath`).
- Пропускаються: порожні назви, дублікати ідентифікаторів, деінсталятори (назва починається з `Uninstall` або ціль — `unins*.exe`) і документи (`.txt`, `.chm`, `.pdf`, `.html`, `.url` до сайтів) — правило в `crates/core`, щоб тестувати.
- Будується у Worker-потоці при старті shell; результат (`Vec<AppEntry>`) передається в UI через `PostMessage` у власність. Поки індекс не готовий, Spotlight показує лише системні команди.
- **Оновлення без опитування:** `FindFirstChangeNotificationW` (з підпапками, імена файлів і папок) на `%APPDATA%\Microsoft\Windows\Start Menu\Programs` і `%ProgramData%\Microsoft\Windows\Start Menu\Programs` + `PackageCatalog` (`PackageInstalling` завершено, `PackageUninstalling` завершено, `PackageUpdating`) з WinRT (`Windows.ApplicationModel.PackageCatalog.OpenForCurrentUser`). Хендли сповіщень чекає пул потоків Windows (`RegisterWaitForSingleObject`), колбек лише робить `PostMessage` і `FindNextChangeNotification`. Події збираються з debounce 2 с (одноразовий таймер UI), потім індекс перебудовується повністю у Worker-потоці.
- Помилка переліку: журнал, попередній індекс лишається (або порожній при старті), наступна подія повторює спробу.

## 4. Клавіша Win (`crates/platform/src/input_hook.rs`)

Наявний LL-хук (потік `newwin-input`) отримує ще один автомат у `crates/core` (`WinKeyTap`, поруч із `LayoutHotkeys`):

- `LWin`/`RWin` down → «Win натиснуто, інших клавіш не було».
- Будь-яка інша клавіша down поки Win тримається → «комбінація», нічого не робимо.
- Win up без комбінації → **хук поглинає цей Win up і ін'єктує через `SendInput` послідовність `VK_NONAME` (0xFC) down, `VK_NONAME` up, Win up** (свою, з сигнатурою NewWin), і надсилає в UI `PostMessage(SPOTLIGHT_TOGGLE)`. Windows бачить Win+щось і «Пуск» не відкриває. Справжній Win up поглинається, бо ін'єкція зсередини хука стає в чергу **після** поточної події — інакше «Пуск» побачив би Win up раніше за `VK_NONAME`.
- `Ctrl+Esc`: `Esc` down при натиснутому Ctrl і без Win → хук **поглинає** цей `Esc` down і відповідний `Esc` up (повертає 1), ін'єктує `VK_NONAME` down+up (щоб NewWin став джерелом останнього вводу й мав право на передній план) і надсилає `SPOTLIGHT_TOGGLE`; `Ctrl` проходить як є.
- Свої ін'єкції (`VK_NONAME`, Win+N) хук пізнає за `dwExtraInfo` = сигнатура NewWin (`0x4E57_4E57`), а не за `LLKHF_INJECTED` взагалі. Це заодно закриває відкладену дрібницю M9 з M2 (хук ігнорував усі ін'єктовані клавіші, зокрема AutoHotkey). Чужі ін'єкції враховуються так само, як фізичні.
- Хук нічого не чекає: лише автомат, `SendInput` і `PostMessage`.
- `win_key = false` у конфігу вимикає обидві гілки (Win і `Ctrl+Esc`), автомат розкладки працює далі. Прапорець читається при старті shell; живе застосування конфігу — у M4.

## 5. Вікно (`crates/ui/src/spotlight.rs`)

- Наявна скляна панель `Panel<C>` з M2 (`WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOREDIRECTIONBITMAP`) з новим вмістом `SpotlightView`. Створюється при кожному відкритті: перший кадр панелей у M2 — 0.9–1.6 мс, тож бюджет 16 мс виконується з запасом, а в простої не тримається жодного вікна чи поверхні.
- **Розмір і місце:** ширина 560 px (за DPI), по центру основного монітора по горизонталі, верхній край на 22 % висоти робочої області. Висота = поле + рядки результатів (0–8) + рядок підказок клавіш; вікно міняє розмір одразу, верхній край не рухається, нові рядки з'являються fade 120 мс.
- **Скло:** наявне рідке скло (`paint_glass`, як у поповерів) з додатковим затемненням `theme::SPOTLIGHT_SHADE` = `rgba(0,0,0,0.22)`, щоб текст читався поверх будь-якого вікна; радіус 16 px.
- **Поле вводу:** текст 20 px, приглушена підказка «Search» у порожньому полі, лупа зліва (векторна іконка), курсор 1.35 px, що блимає з інтервалом системи (`GetCaretBlinkTime`; при `INFINITE` не блимає; блимання зупиняється, коли вікно сховане — жодних таймерів у простої).
- **Рядок результату:** назва 13 px, збіг жирним, тип справа (*App* / *System*) приглушено; вибраний рядок — у пігулці, яка перетікає між рядками (твін, як пігулка активної програми на барі).
- **Підказки клавіш внизу:** `↑↓ select · ↵ open · Ctrl ↵ run as administrator · Esc close`, приглушено, 11 px.
- **Анімація:** як у панелей M2 — поява fade + зсув на 6 px, 150 мс; зникнення 120 мс. Під час зникнення ввід ігнорується.
- **Блимання курсора й скидання підтвердження** — одноразовий таймер панелі на найближчий момент зміни (`wake_at`), без кадрового таймера.
- **Фокус:** при показі `SetForegroundWindow` + `SetFocus`. Права на передній план: хук щойно викликав `SendInput`, тож процес NewWin — джерело останнього вводу, і Windows дозволяє. Для `Ctrl+Esc` і лупи — те саме (клік по бару / свій ввід). Проба 2 перевіряє це. Якщо Windows однаково не віддасть фокус, запасний шлях — `AttachThreadInput` до потоку поточного активного вікна на час `SetForegroundWindow`.
- **Ввід тексту:** `WM_CHAR` (зокрема сурогатні пари), без IME (українській і англійській не потрібен; IME — поза межами).
- Рендер лише при змінах (ввід, твін, блимання курсора); циклу кадрів немає.

## 7. Надійність

- Падіння NewWin знімає хук разом із процесом → Win знову відкриває рідний «Пуск». Watchdog перезапускає shell, хук повертається.
- Windows знімає LL-хук, що відповідає довше за `LowLevelHooksTimeout`; наш хук робить лише автомат, `SendInput` і `PostMessage`, тож це не загрожує.
- Індекс не зібрався → лише системні команди; наступна подія повторює.
- Explorer перезапустився → індекс не залежить від explorer (папка `AppsFolder` доступна через shell API в нашому процесі); перебудова за `TaskbarCreated` не потрібна.
