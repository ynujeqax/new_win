# NewWin 1.0.1: іконки програм (доповнення до дизайну)

Дата: 2026-10-25
Статус: погоджено з користувачем, чекає рев'ю специфікації

Доповнює [2026-10-21-newwin-design.md](2026-10-21-newwin-design.md) §6 (запущені програми) і §9 (Spotlight), а також [M2 трей](2026-10-22-newwin-m2-tray-design.md), де записано «іконки (`HICON`) не зберігаємо: у трей-панелі лише текст». Де документи розходяться, діє цей.

## 1. Що погоджено з користувачем

- **Навіщо:** однакові назви не розрізнити. Приклад — два «Claude» у Spotlight: програма зі Store і ярлик `Claude.lnk`, що запускає `powershell.exe` (без власної іконки, тому Windows показує іконку PowerShell).
- **Звичайні кольорові іконки Windows** на барі (запущені програми), у Spotlight і в списку трею під `⌃`. Решта інтерфейсу лишається монохромною й текстовою, у склі.
- Бар: **іконка + назва**. Трей: лишається списком під `⌃`, з іконкою в кожному рядку.
- Підхід A: бар і Spotlight беруть іконку так, як її показують Провідник і «Пуск»; трей — ту іконку, яку програма сама передала в трей.
- Версія **1.0.1**, ставиться оновленням поверх 1.0.0.

## 2. Вигляд

- Іконка — квадрат **16 логічних px** (за DPI: 16 / 20 / 24 / 32 фізичних), у кольорі, без тонування й без тла. Відступ до тексту **6 логічних px**.
- **Бар.** Іконка ліворуч від назви в тій самій пігулці. Ширина пігулки = відступи + іконка + відступ + текст. Коли місця бракує, `fit_labels` скорочує спершу назви; мінімальна ширина пігулки — відступи + іконка (назва зникає повністю, іконка лишається). Далі, як і раніше, кнопка переповнення.
- **Spotlight.** Іконка ліворуч від назви результату; для системних команд (*NewWin Settings*, *Shut down*…) іконки немає, але місце під неї лишається, щоб назви стояли в один стовпчик. Мітка праворуч (*App* / *System*) без змін.
- **Трей.** Іконка ліворуч від підпису в кожному рядку списку.
- **Поява.** Місце під іконку резервується одразу (текст не стрибає); сама іконка проявляється за **150 мс** (непрозорість 0 → 1), коли готова. Якщо іконки немає (програма без неї, помилка), місце лишається порожнім — без заглушки.
- Неактивне вікно бару/Spotlight іконки не приглушує (як Windows).

## 3. Звідки іконки

| Де | Джерело | Ключ кешу |
|---|---|---|
| Бар | `GroupKey::AppId(aumid)` → `shell:AppsFolder\<aumid>`; `GroupKey::ExePath(path)` → файл `path` | `Shell(рядок джерела)` + px |
| Spotlight | `Candidate.id` (ім'я розбору AppsFolder) → `shell:AppsFolder\<id>` | `Shell(рядок джерела)` + px |
| Трей | `hIcon` з `NOTIFYICONDATA` (32-бітне значення; дескриптори іконок спільні для всіх процесів сесії) | `Tray(hIcon)` + px |

- **Shell-іконки** (`SHCreateItemFromParsingName` + `IShellItemImageFactory::GetImage(px, SIIGBF_ICONONLY)` → 32-бітний DIB з альфою) беруться **у фоновому потоці** `newwin-worker` (там уже є COM для індексу програм). Нова задача `Job::Icon` → повідомлення `IconReady` в UI-потік.
- **Іконки трею** перетворюються в UI-потоці (`DrawIconEx` у 32-бітну DIB-секцію; < 1 мс на іконку), лише для рядків, видимих у відкритому списку.
- Трей: розбір `NOTIFYICONDATA` додатково читає `hIcon` (зсув 20 у 32-бітній структурі), модель зберігає його в `TrayIcon.hicon`; `NIM_MODIFY` з `NIF_ICON` оновлює значення, без `NIF_ICON` — лишає. Нове значення → новий ключ → нове зображення (так приходять значки непрочитаного й зміни стану).
- **Пікселі:** BGRA перемножується на альфу (premultiplied) для D2D. Іконка без жодного ненульового альфа-байта (старий формат із маскою) вважається непрозорою там, де маска пропускає, — для `DrawIconEx` це вже враховано, для shell-зображень такий випадок: альфа = 255.

## 4. Кеш і пам'ять

- **Кеш зображень** (CPU, `crates/core`): до **128** записів, найдавніше використаний витісняється першим. Стан запису: *очікує* / *готово(зображення)* / *немає*. Повторний запит того самого ключа під час очікування не ставить ще одну задачу. *Немає* не перепитується, доки ключ не зміниться (переіндексування Spotlight чистить записи `Shell` зі станом *немає*).
- **D2D-бітмапи** створюються з кешу при першому малюванні й живуть разом із D2D-пристроєм; втрата пристрою або його звільнення після простою (як зараз) — бітмапи створюються знову з CPU-кешу.
- Запити лише для того, що видно: усі пігулки бару; у Spotlight — лише показані результати (до `max_results`, 8); у треї — видимі рядки відкритого списку.
- Очікувана ціна: ≈1 KB на іконку при 100 % (16×16×4), ≈4 KB при 200 %; +1–2 MB пам'яті shell. Простій — **нуль нових пробуджень**: усе за подіями (вікно з'явилось, Spotlight показав результати, трей змінив іконку).
- Зміна DPI → інший px → нові запити; старі записи витісняються самі.

## 6. Надійність

- Будь-яка помилка Windows під час отримання іконки → *немає*, у журнал рядок рівня `debug`; NewWin не падає й не повторює запит у циклі.
- Недійсний або вже знищений `hIcon` трею → `DrawIconEx` повертає помилку → *немає* для цього значення.
- Фоновий потік зайнятий індексом програм → іконки чекають у черзі; бар уже показує назви.

## 7. Тести й приймання

**Автотести (спершу падають):**
- `premultiply` (прозорий, напівпрозорий, непрозорий піксель); зображення без альфи стає непрозорим.
- Кеш: витіснення 129-го найдавнішого, один запит на ключ під час очікування, *немає* не перепитується, очищення *немає* для `Shell`.
- Джерела: `GroupKey::AppId` → `shell:AppsFolder\…`, `ExePath` → шлях; кандидат Spotlight → `shell:AppsFolder\<id>`; системна команда → без джерела.
- Трей: `hIcon` із сирих байтів `NOTIFYICONDATA`; `NIM_MODIFY` без `NIF_ICON` зберігає `hicon`.
- `fit_labels` з мінімальною шириною «лише іконка».
- Інтеграційний (платформа): `shell_icon` для `C:\Windows\explorer.exe` дає 16×16 із ненульовою альфою; `hicon_image` для `LoadIconW(IDI_APPLICATION)` дає зображення.

**Живий чекліст:**
- [ ] Spotlight `claude`: два рядки з різними іконками (Claude і PowerShell).
- [ ] Бар: іконки запущених програм, зокрема програм зі Store (Калькулятор, Параметри); вузький бар — назви скорочуються, іконки лишаються.
- [ ] Трей `⌃`: іконки в рядках; іконка, що змінюється (Telegram з непрочитаними або інша), оновлюється.
- [ ] Масштаб 125/150 % — іконки чіткі.
- [ ] Простій 10 хв: CPU ≈ 0 %, пам'ять shell не більше ніж +2 MB від 1.0.0 (14.8 MB пік).
- [ ] Оновлення 1.0.0 → 1.0.1 інсталятором: налаштування на місці, About показує 1.0.1.

## 8. Поза межами 1.0.1

- Іконки в списках *Tray* / *Items* вікна налаштувань.
- Налаштування «вимкнути іконки».
- Іконки окремих вікон (як різні профілі браузера в таскбарі Windows): береться іконка програми.
