# NewWin 1.0.1: іконки програм — план реалізації

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** кольорові іконки Windows на барі (запущені програми), у Spotlight і в списку трею; версія 1.0.1.

**Architecture:** Чиста логіка (зображення, ключі, кеш) — `crates/core/src/app_icon.rs`. Отримання пікселів — `crates/platform/src/app_icon.rs`: shell-іконки у фоновому `newwin-worker` (`Job::Icon` → `IconReady`), іконки трею з їхнього `hIcon` в UI-потоці. `crates/ui` малює `Rc<IconImage>` через кеш D2D-бітмапів і плавно проявляє їх; shell просить іконки лише для видимого.

**Tech Stack:** Rust 2024, `windows` 0.62 (Shell `IShellItemImageFactory`, GDI `DrawIconEx`/`GetDIBits`, Direct2D), Inno Setup 7.1.

**Spec:** [docs/superpowers/specs/2026-10-25-newwin-1.0.1-icons-design.md](../specs/2026-10-25-newwin-1.0.1-icons-design.md)

## Global Constraints

- Іконка **16 логічних px** (`scale(16, dpi)`), відступ до тексту **6 логічних px**; кольорова, без тонування й тла.
- Проявлення **150 мс** (непрозорість 0 → 1); місце під іконку резервується одразу; без іконки — порожнє місце, без заглушки.
- Кеш зображень — **128** записів, LRU; стани *очікує* / *готово* / *немає*; *немає* не перепитується, доки ключ не зміниться; переіндексування Spotlight чистить *немає* для shell-ключів.
- Shell-іконки лише у `newwin-worker`; іконки трею — у UI-потоці, лише для видимих рядків відкритого списку.
- Простій — нуль нових пробуджень; пам'ять shell ≤ +2 MB від 1.0.0 (14.8 MB пік).
- Помилки отримання іконки → *немає* + `log::debug!`, без повторів у циклі.
- Системні команди Spotlight — без іконки, але з місцем під неї.
- Версія workspace `1.0.1`.

## Review Focus

1. **Програма, чий exe недоступний** (процес адміністратора, системний, видалений файл) → без іконки, назва лишається, запит не повторюється. Тест: `missing_is_not_asked_again` (Task 1).
2. **Знищений `hIcon` трею** (програма вийшла між оновленням і малюванням) → `None`, без падіння. Тест: `a_dead_hicon_gives_none` (Task 3).
3. **Програма, що анімує іконку трею** (десятки нових `hIcon` за секунду) → кеш не росте понад 128. Тест: `the_cache_never_holds_more_than_128` (Task 1).
4. **Зміна DPI з повним кешем** → нові запити з новим px, старі витісняються. Тест: `a_key_includes_its_size` (Task 1).
5. **Швидке друкування в Spotlight** (результати змінюються щокадру) → один запит на ключ, доки він очікує. Тест: `one_job_per_key_while_waiting` (Task 1).

`IconCache` узагальнений (`T` = `Rc<IconImage>` в UI-потоці): чисте ядро без `Rc`, тести на `T = u32`. LRU — лічильник звертань; витіснення при вставці 129-го.
